Vessel 并行开发

git worktree + Steward + eva.json

并行开发是什么

Vessel 支持多个 Claude Code session 同时工作在不同任务上，互不干扰。 核心是 git worktree 隔离代码 + 端口隔离 跑独立 backend + Steward 做任务调度协调。

关键约束（不能绕过）

I1
BACKLOG.md 是唯一写入点
只有主线 Claude 改它，worker 不直接改
I8
三层执行白名单
读操作自动跑 · 写操作等 ack · 破坏性操作等明示肯定
I11
Dispatch 必须用户拍板
Claude 给分析 + 推荐，但不静默选 spawn/stay
I13
Worker 代码 PR 不默认 auto-merge
文档类 PR 可 auto-merge，代码类必须主线 + 你 review

Task 状态机

stateDiagram-v2 [*] --> planned : 加待办 planned --> in_progress : 开始干 planned --> blocked : blocked 因为 in_progress --> done : 收线 ✓ in_progress --> blocked : 中途暂停 blocked --> planned : unblock in_progress --> dropped : drop 因为 planned --> dropped : drop 因为 done --> [*] dropped --> [*]

done 和 dropped 永久保留，作为审计 trail

核心原则：你从来不需要手敲 CLI 命令——把短语粘到 Claude，它跑命令、问 ack、收尾。

完整操作流程

1
开始新会话 → Boot

每次打开新 Cursor/Claude Code 窗口时，先触发 boot ritual，让 Claude 知道现在 backlog 状态。

/boot

Claude 会 echo：Backlog: N in_progress · M planned · K blocked

2
选一个任务开干

告诉 Claude 你想开始哪个 task。它会做 Dispatch 分析然后等你拍板。

开始干 <task-id>
Claude 会给你这样的分析：
Task: m2-voice-proposal
  size=M · priority=P2
  parallel_safe_files=["docs/proposals/"]

Spawn 分析：
  • size=M → 倾向 spawn
  • 零文件冲突 → spawn 安全
  • 主窗口：idle

建议：SPAWN
理由：文档任务，独立性强，开新窗口不亏
ok spawn
开新 worktree 窗口
ok stay
在本窗口做
用户做
你自己做，Claude 跟踪
2b
如果选 spawn：Claude 给你 5 步命令

Claude echo 以下步骤，你 ok 后它执行：

1. git worktree add ~/Desktop/Vessel-<name> -b feat/<branch>
2. 写 eva.json 注册 worktree（port / dataDir / owns）
3. 新目录写 .env.local (PORT=<N>)
4. 你手动打开新 Cursor 窗口 → 指向那个目录
5. 给新 session 的启动 prompt 模板
3
Worker 完成 → 发完成信号

Worker session 完成 task 时，自己跑：

./scripts/steward-signal-done.sh <task-id> --pr <PR_URL> --summary "1行描述"

写入 ~/.vessel/spawn-done/<task-id>.json。Worker 不直接改 BACKLOG.md。

4
主线查看完成项

在主线窗口粘：

pnpm eva:collect

Claude 扫 spawn-done 目录，列出所有 pending 完成项给你看。

5
收线 → 清理 worktree
ok 收线 <task-id>

Claude 做：

  • 改 BACKLOG: status → done + completed_at
  • 清 spawn-done flag
  • 跑 pnpm eva:hook pre-remove --dry-run <name> 预演清理
  • 等你 ok → 执行清理（pkill backend / rm worktree 目录）
  • git worktree remove

三层执行白名单（I8）

Read-only auto — Claude 自动跑，不问你
git status / ls / cat / pnpm eva:sessions
Write needs ack — echo 命令，等你 ok
git commit / 改 BACKLOG.md / gh pr edit
Destructive: 明示肯定 — 必须你主动短语
rm -rf / git push --force / worktree remove
点击卡片右上角按钮一键复制。粘到任意 Claude Code / Cursor 窗口即可触发。

eva.json — worktree 注册表

项目根目录，机器可读，是并行状态的单一来源。查看：pnpm eva:status

{
  "version": 1,
  "worktrees": [
    {
      "name": "feat-voice-worker",       // worktree 名称
      "branch": "feat/voice-capability", // git 分支
      "path": "~/Desktop/Vessel-voice",  // 独立目录
      "port": 3033,                      // 独立后端端口
      "dataDir": "~/.claude-web-voice",  // 独立数据目录
      "owns": [                          // 锁定的文件/函数
        "packages/backend/src/routes/voice.ts"
      ],
      "status": "active",                // active / done / released
      "since": "2026-05-19T08:00:00Z",
      "hooks": {
        "post-start": "PORT=3033 pnpm dev:backend &",
        "pre-remove": "pkill -f voice-backend; rm -rf ~/.claude-web-voice"
      }
    }
  ]
}

Lifecycle Hooks（H13）

手动触发，不自动运行。4 个生命周期点：

pre-start
开始前准备（install deps 等）
post-start
启动后动作（跑 backend 等）
post-merge
PR merge 后（通知等）
pre-remove
清理前（pkill / rm 等）⚠️ 需 --yes
pnpm eva:hook pre-start <worktreeName>
pnpm eva:hook post-start <worktreeName>
pnpm eva:hook pre-remove --dry-run <worktreeName>   # 先预演
pnpm eva:hook pre-remove --yes <worktreeName>        # 含 rm/pkill 时必须 --yes

Worker PR 政策（I13）

✗
代码类 PR（backend / frontend / ios-native / scripts）
Worker 可 push + gh pr create，但不 auto-merge。必须等主线 + 你 review 后手动 merge。
✓
文档类 PR（docs / proposals / ADR / retrospectives）
Worker 在 signal 里备注 "ready for auto-merge"，主线确认后 gh pr merge --auto。
