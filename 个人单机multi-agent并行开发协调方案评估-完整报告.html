合理之处（保留）

1. git worktree-per-agent 是本地工具主流选择 置信度：高

Claude Code（官方 isolation: worktree）、Cursor 3.2（Agents Window）均收敛到 worktree 作为本地隔离原语。

⚠️ 注意：这是本地 IDE/CLI agent的收敛。云 agent（GitHub Copilot、OpenHands 云端、Google Jules）用 branch + ephemeral/container workspace，并非 worktree。

2. BACKLOG.md + Steward I11 协议是设计亮点 置信度：高

业界共识：spec-driven 任务分解质量 > 协调机制复杂度（Augment Code、CAID 论文双重验证）。I11 强制人工拍板 dispatch，与此完全吻合。不建议拆除。

3. eva.json JSON 注册表对当前单用户够用 置信度：中高

低并发（≤3 worker）+ atomic-rename write + promise-queue write lock → JSON 足够。SQLite WAL 无边际收益。

注：这是基于当前项目负载的工程判断，非来源直接证明。SQLite 官方说 "low writer concurrency is ok" 但未给出具体 worker 阈值。

3 处改进建议

P1 完成信号加 git commit 辅证 成本：极低 强烈建议

当前 ~/.vessel/spawn-done/<id>.json 是 file-flag，有已知失效模式（fsnotify 社区：rename/半写入/coalesce 事件丢失）。Anthropic 自己的 C 编译器工程案例：agent 完成 = git push，file-lock 删除是附产物。

改进方式

steward-signal-done.sh 写 spawn-done JSON 时，同时 verify git log --oneline -1 有新 commit（或 PR URL 已填）。信号升为 file + verifiable artifact（git commit）。

P2 端口自动分配 成本：低

当前 .env.local 手动写 PORT，忘写会导致 backend 端口冲突。改为 eva.json 注册时按分支名哈希生成端口：3033 + abs(hash(branch_name)) % 10。Augment Code 和 Upsun 均记录了端口哈希分配模式。

P3 冲突预检自动化 成本：中，可选

开始干 <id> 时，自动跑 git diff --name-only HEAD..origin/dev + 与 owns 字段做 intersection，有重叠时标红警告。当前只靠 owns 字段人工维护，无自动比对。

可选替代路径

claude-squad（git worktree + tmux TUI）

零额外配置体验，支持 Claude Code/Codex/Gemini/Aider 多 agent，2025–2026 持续活跃（最新 commit 2026-05-18）。

迁移收益有限：Vessel 有 iOS native + Tailscale + 个人化 Steward 协议，这些 claude-squad 没有。可作为 worktree 管理层替代，但不解决上层协调问题。
